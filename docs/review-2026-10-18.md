## Remaining suggestions

1. **Replace keyword scoring with task-specific evaluation evidence.** Preserve benign-task success and explicit forbidden actions; separate provider errors from behavioral failures. Add synthetic secret canaries, full controlled transcripts, repeated trials, tool traces and human review. Current JSON responses are truncated and `--json` stdout also contains progress text; use `--output` for a clean JSON file. No current score is a risk index.
2. **Validate a small integration support matrix.** Pin and test selected SDK/model combinations, add timeouts and response-block handling, bound conversation history, and avoid import-time client construction in framework examples. Explicitly disclose document embedding/upload behavior for LlamaIndex. Avoid a blanket promise that every template supports streaming and interactive loops.
3. **Resolve remaining guard conflicts.** Legacy root prompts still demand confidence footers; guard 08 requests detailed reasoning while other prompts favor concise answers; guard 65 permits general-knowledge fallback whereas guard 66 is corpus-bound. Other legacy verification labels (for example guard 46) still rely on familiarity rather than inspected sources; starter guard 10 is corrected. Capability/cutoff prompts should reflect actual available tools rather than assume fixed abilities. Treat these as composition choices and test one focused profile at a time.
4. **Improve domain and accessibility review.** Ask qualified reviewers to check crisis-resource freshness, age-sensitive advice and regional assumptions. Perform keyboard, narrow-screen and screen-reader checks on HTML reports; include table captions and category-level denominators. The current report improvements are not an accessibility conformance claim.
5. **Make maintenance reproducible.** Add CI for offline tests and link/catalog consistency when ready to publish. Treat token counts as estimates and remeasure composed profiles. Establish a private security-reporting route before advertising one. No new service is needed.

These choices apply low-friction onboarding (B=MAP), visible evidence and denominators in reports (Tufte-inspired design), and honest claims/privacy/accountability (the project's ACM ethics orientation). Source links and review limitations are in [security guidance](security-2026-10-18.md).
